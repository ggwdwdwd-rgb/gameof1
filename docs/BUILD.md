# BUILD.md — сборка APK и раздача его людям

Магазина приложений здесь нет: APK собирается вручную и передаётся файлом или
ссылкой. Всё, что ниже, делается из папки `app`.

---

## 0. Главное про подпись — прочитать до первой сборки

Android разрешает обновить установленное приложение только APK **с той же
подписью**. Подпись — это ключ (keystore), которым APK подписан при сборке.

Что происходит, если подпись изменилась: новый APK не встанет поверх старого
(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`, на телефоне это «Приложение не
установлено»). Единственный выход — удалить старое. А удаление уносит:

- **приватные ключи устройства** (лежат в `expo-secure-store`, то есть в Android
  Keystore внутри данных приложения — оттуда их нельзя ни скопировать, ни
  забэкапить);
- **всю локальную переписку** (`expo-sqlite`, тоже в данных приложения).

Расшифровать прежние сообщения после этого нечем: сервер хранит только
зашифрованные блобы, а ключ к ним был на телефоне. Человек становится **новым
участником** — нужен новый код приглашения, а прежний аккаунт удаляется главным
(docs/DEPLOY.md §8a).

Отсюда два правила, которые нельзя нарушать:

1. **Не менять `android.package`** в `app.json` (сейчас `re.familymessenger.app`).
   Для Android это имя приложения; другое имя — другое приложение.
2. **Не менять ключ подписи.** EAS создаёт его один раз для этого пакета и
   переиспользует во всех сборках и профилях. Сломать это можно двумя способами:
   пересоздать credentials в панели Expo или собрать локально своим новым
   ключом.

Поэтому первый шаг — не сборка, а бэкап ключа.

## 1. Что нужно один раз

- Node 20+ и папка `app` с установленными зависимостями (см. `app/README.md`).
- Бесплатный аккаунт Expo: `npx eas login`.
- Больше ничего: компиляция идёт в облаке EAS. Android Studio нужен только для
  локальной сборки (§7).

## 2. Сначала — забрать и сохранить ключ подписи

Ключ уже создан: его сделал EAS при первой `preview`-сборке, и им подписаны все
APK, которые стоят у людей. То есть создавать нечего — надо **забрать копию**,
пока она есть только на серверах Expo. Потеря аккаунта Expo без такой копии
означает, что обновить установленное приложение больше нечем никогда: останется
только удалять его у всех, а это переписка и ключи под нож.

Шаг требует компьютера — команда интерактивная, с телефона её не пройти:

```bash
cd app
npx eas credentials -p android
```

В меню выбрать профиль (`production`), затем
`credentials.json: Upload/Download credentials between EAS servers and your local json`
и `Download credentials from EAS to credentials.json`.

Появятся два файла: `credentials.json` (пути и пароли) и `keystore.jks` (сам
ключ). Оба **уже в `.gitignore`** — в репозиторий они попадать не должны.

Скопировать их туда, где они не пропадут вместе с ноутбуком: менеджер паролей,
зашифрованный архив на флешке, что угодно офлайновое. Из `credentials.json`
нужны все четыре значения — `keystorePath`, `keystorePassword`, `keyAlias`,
`keyPassword`; без паролей файл ключа бесполезен.

Пока цел аккаунт Expo, ключ хранится и там, так что этот бэкап — страховка от
потери аккаунта. Потерять и то и другое означает, что все участники начинают с
нуля.

## 3. Обычная сборка релизного APK

### Из браузера (работает с телефона)

**Actions → «Build release APK (EAS)» → Run workflow.** Это
`.github/workflows/build-release-apk.yml`: сначала отдельной задачей проходят
тесты крипто-пакета, `tsc`, `check:sql`, `check:imports`, `check:android` и сборка
бандла, и только потом собирается APK. Сломанный бандл до людей не доедет.

Готовый APK публикуется в GitHub Release с тегом `release-N`, там же в описании —
что сделать после установки. Компьютер не нужен, консоль VPS не нужна.

Рядом лежат два прежних workflow: `build-preview-apk.yml` (то же самое, но без
`autoIncrement` и без проверок) и `build-dev-apk.yml` (dev-client для отладки с
Metro).

### Почему сборка идёт на раннере, а не в облаке EAS

Бесплатный план Expo даёт ограниченное число **облачных** Android-сборок в месяц.
Оно кончается быстрее, чем кажется: три дня активной работы — и в логе появляется

```
This account has used its Android builds from the Free plan this month,
which will reset in 28 days
```

после чего облачная сборка недоступна до начала следующего месяца. Поэтому
workflow-и запускают `eas build --local`: компилирует сам раннер GitHub, и эта
квота не тратится вообще.

**Ключ подписи при этом тот же.** `--local` берёт credentials с серверов Expo —
ровно для этого шагу нужен `EXPO_TOKEN`. Это не деталь: APK с другой подписью не
встал бы поверх установленного, и людям пришлось бы удалять приложение вместе с
ключами и всей перепиской (§0). В логе успешной сборки это видно строкой
`Using Keystore from configuration: Build Credentials …`.

Что за это платим: сборка занимает 20–40 минут вместо очереди EAS, и шаг требует
JDK 17 (`actions/setup-java`) и `GRADLE_OPTS=-Xmx4g` — без heap-лимита Gradle
падает с `OutOfMemoryError` на оптимизации бандла.

### С компьютера

```bash
cd app
npx eas build --profile production --platform android
```

EAS напечатает ссылку на страницу сборки; там же кнопка скачивания APK и QR-код
для установки прямо на телефон. Сборка идёт 10–20 минут, компьютер после старта
можно закрыть — ссылку потом достать так:

```bash
npx eas build:list --platform android --limit 5
```

Про версии: в `eas.json` стоит `appVersionSource: "remote"` и
`autoIncrement: true` для профиля `production`, поэтому `versionCode` (внутренний
номер сборки) увеличивает сам EAS. Руками ничего править и коммитить не нужно.
Видимую версию (`0.1.0`) можно менять в `app.json` → `expo.version`, когда есть
что назвать новой версией.

Профили в `eas.json`:

| Профиль       | Зачем                                                        |
|---------------|--------------------------------------------------------------|
| `development` | dev-client для отладки с `npx expo start --dev-client`       |
| `preview`     | обычный APK для проверки перед раздачей                      |
| `production`  | то, что раздаётся людям (`autoIncrement`)                    |

`preview` и `production` — оба release-сборки, подписаны одним ключом проекта,
поэтому ставятся друг поверх друга как обновления. `development` — отладочный
вариант, и подпись у него может отличаться; проверяй установку dev-client поверх
релиза на одном телефоне, а не сразу на всех.

## 4. Перед сборкой: проверки

Ни одна из них не требует телефона и не лезет в сеть, кроме `e2e`. Всё вместе —
минут пять.

```bash
cd packages/crypto && npx vitest run          # 31 тест криптографии
cd ../app && npx tsc -p tsconfig.json --noEmit
npm run check:sql                              # SQL локальной базы на настоящем SQLite
npm run check:android                          # разрешения не вырезаны из APK
npm run check:imports                          # нативные модули не уронят старую сборку
npx expo export --platform android             # бандл собирается (ловит ошибки импортов)
cd ../server && npx tsc -p tsconfig.json --noEmit && npm run test:users
```

`check:imports` тоже появился не зря: обычный импорт пакета с нативной частью
требует нативный модуль сразу, на загрузке JS-модуля, и на сборке без него
приложение падает при запуске целиком — до соединения с сервером. Выглядит это
как «сообщения не идут», а причина не видна ниоткуда. Я наступил на это дважды
(`expo-application`, `expo-local-authentication`), теперь проверка ловит такой
импорт до сборки.

`check:android` появился не зря: плагин `expo-image-picker` умеет вырезать
разрешения из манифеста (`tools:node="remove"`), и однажды из APK так пропали
микрофон и камера — приложение собиралось и запускалось, а голосовые записать
было нельзя.

Сквозная проверка сервера (нужен запущенный сервер и одноразовый код):

```bash
cd server
PORT=8099 DB_PATH=./data/e2e.db npm run dev          # в отдельной консоли
PORT=8099 DB_PATH=./data/e2e.db npm run invite:create
WS_URL=ws://127.0.0.1:8099/ws npm run test:e2e -- КОД
```

И то же самое кодом самого приложения (шифрование и chatId берутся из `app/src`):

```bash
cd app
WS_URL=ws://127.0.0.1:8099/ws npm run check:send -- КОД1 КОД2
```

## 5. Как раздать и установить

Самое простое — отправить ссылку со страницы сборки: человек открывает её на
телефоне, жмёт установку, Android сам предложит разрешить установку из этого
источника. Можно и просто послать файл APK.

На чистом телефоне по пути встретится:

- **«Установка из неизвестных источников»** — разрешить для того приложения,
  через которое открыт файл (браузер, мессенджер, файловый менеджер).
- **Play Protect: «Небезопасное приложение»** — приложение не из магазина и
  подписано незнакомым Google ключом. Нажать «Всё равно установить» /
  «Подробнее → Установить». Это ожидаемо и другого способа для APK вне магазина
  нет.
- **Обновление поверх** — если подпись та же, установка проходит как обычное
  обновление: переписка, ключи и настройки остаются на месте. Удалять старое
  приложение **не нужно и нельзя** (см. §0).

После установки стоит попросить человека проверить: **Настройки → Диагностика →
Версия**. Там `0.1.0 (7)` — видимая версия и номер сборки; по нему сразу понятно,
обновился человек или нет.

Ещё две настройки на телефоне, без которых уведомления работают плохо (о них
написано и на экране настроек):

- Приложения → Cry → Батарея → «Без ограничений»;
- на Samsung дополнительно Батарея → «Спящие приложения» — Cry там быть не
  должно.

## 6. Свой ключ вместо сгенерированного EAS

Ключ из §2 и так твой — он просто создан автоматически. Заводить новый нужно
только если старый потерян вместе с доступом к аккаунту Expo, и тогда всё равно
придётся переустанавливать приложение всем участникам (§0).

Создать ключ:

```bash
cd app
keytool -genkey -v -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass ПАРОЛЬ_ХРАНИЛИЩА -keypass ПАРОЛЬ_КЛЮЧА -alias cry \
  -keystore android/keystores/release.keystore \
  -dname "CN=re.familymessenger.app,OU=,O=,L=,S=,C=RU"
```

Рядом создать `app/credentials.json`:

```json
{
  "android": {
    "keystore": {
      "keystorePath": "android/keystores/release.keystore",
      "keystorePassword": "ПАРОЛЬ_ХРАНИЛИЩА",
      "keyAlias": "cry",
      "keyPassword": "ПАРОЛЬ_КЛЮЧА"
    }
  }
}
```

И указать в `eas.json` профилю, что брать ключ локально:

```json
"production": {
  "credentialsSource": "local",
  "distribution": "internal",
  "autoIncrement": true,
  "android": { "buildType": "apk" }
}
```

`credentials.json`, `*.keystore` и `android/keystores/` перечислены в
`.gitignore` — так и оставить.

`validity 10000` — это ~27 лет. Меньше ставить нельзя: истёкшим ключом
подписывать обновления не получится, а смена ключа стоит переустановки у всех.

## 7. Сборка без облака EAS

Если облако недоступно (или просто не хочется его использовать), тот же процесс
запускается на своей машине. Нужны Android SDK и NDK, JDK (подходящий ставится
вместе с Android Studio) и место на диске:

```bash
cd app
npx eas build --profile production --platform android --local
```

Аккаунт Expo всё равно нужен (`eas login`): локальная сборка обращается к EAS
только чтобы проверить проект и, при `credentialsSource: "remote"`, скачать ключ.

Совсем без EAS — через нативный проект:

```bash
cd app
npx expo prebuild --platform android    # создаёт папку android/ (она в .gitignore)
cd android && ./gradlew assembleRelease
```

APK окажется в `android/app/build/outputs/apk/release/`. Подпись при этом надо
настроить самому: положить keystore в `android/app/`, прописать
`MYAPP_UPLOAD_STORE_FILE`, `MYAPP_UPLOAD_KEY_ALIAS`,
`MYAPP_UPLOAD_STORE_PASSWORD`, `MYAPP_UPLOAD_KEY_PASSWORD` в
`~/.gradle/gradle.properties` (не в проект — там они попали бы в репозиторий) и
добавить `signingConfigs.release` в `android/app/build.gradle`. Иначе gradle
подпишет сборку отладочным ключом, и она не встанет поверх нормальной.

Важно: `android/` пересоздаётся при каждом `prebuild`, поэтому все правки внутри
неё живут до следующего запуска. Постоянные изменения делаются через
`app.json`/плагины, а не правкой `android/` — по этой же причине папка и не лежит
в репозитории.

## 8. Если что-то пошло не так

**«Приложение не установлено» при обновлении.** Подпись не совпала. Не удаляй
приложение сразу — сначала проверь, тем ли ключом собран APK (§0, §2). Если APK
действительно подписан другим ключом, собери заново правильным. Удаление — это
потеря переписки и ключей.

**`This account has used its Android builds from the Free plan this month`.**
Кончилась квота **облачных** сборок Expo, до начала следующего месяца её не
вернуть. Код тут не при чём. Workflow-и в репозитории собирают локально
(`--local`) и этой квоты не тратят — если увидел эту строку, значит сборка
запущена без `--local` (например командой с компьютера); добавь флаг либо жди
сброса квоты.

**Сборка падает на `expo-modules-autolinking` / не находит `keep-alive`.**
В `app/package.json` должно быть
`"expo": { "autolinking": { "nativeModulesDir": "./modules" } }` — без этого
локальный нативный модуль работы в фоне не подхватывается (значения по умолчанию
у этой настройки нет). Проверить:

```bash
cd app && npx expo-modules-autolinking search --platform android
```

**В собранном APK нет микрофона или камеры.** Плагин вырезал разрешение из
манифеста. `npm run check:android` показывает это до сборки.

**Уведомления приходят только пока приложение открыто.** Это не сборка, а
настройки телефона и переключатель «Работать в фоне» — см. ARCHITECTURE.md §12.
